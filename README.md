# 长按语音输入

DSH Web 客户端插件，复用 DSH 实验性语音输入：长按独立麦克风按钮约 0.5 秒开始录音；松手后停止并识别；向上滑动约 70 像素进入取消区，松开取消，也可滑回继续。麦克风短按使用原生普通录音，输入框完全保留原生编辑与iOS长按粘贴。录音期间整输入卡显示真实音量波形，中央七彩球随音量缩放，并显示滑动取消进度。到达取消区后卡片变红。空识别结果自动复位，实际权限/服务/草稿冲突错误仍保留原反馈。

Safari 麦克风授权由浏览器控制，本插件不能绕过。可尝试在当前站点的 Safari 网站设置中将麦克风从“询问”改为“允许”（具体入口随 iOS 版本变化），并固定使用同一 HTTPS 域名。每次录音沿用原服务的一次麦克风请求，动画不额外申请麦克风；录音结束即释放，不为规避弹窗持续监听。

## 前提与安装

先在 DSH 插件管理中启用并完成实验性语音输入的配置及模型准备。浏览器需要麦克风权限以及安全上下文（HTTPS 或 localhost）。本插件不包含语音识别服务或模型，也不会自动下载它们。服务未就绪时保留原始设置入口。

通过 DSH 插件管理器安装 `dsh-plugin-voiceinputwithpress`，或使用 CLI：

```sh
dsh plugin --profile <profile> add dsh-plugin-voiceinputwithpress@0.1.10
```

从源码开发安装：

```sh
npm run build
dsh plugin --profile <profile> add file:/absolute/path/to/dsh-plugin-voiceinputwithpress
```

从 0.1.9 升级可重新执行上面的固定版本安装命令。**交互变化：长按说话已从输入框移到麦克风按钮，输入框长按恢复系统粘贴；已有草稿使用普通录音，不自动发送。**

启用后刷新现有 DSH 页面；卸载或停用本插件可恢复原有行为。具体安装方式请以所用 DSH 版本的插件管理器为准。

## 发送与限制

仅空输入框且没有附件时接管麦克风按钮长按；已有任何文字（包括空格）或附件时不接管，沿用普通录音识别填入草稿，不自动发送。手机触摸和PC鼠标均可长按麦克风；短按使用原生录音，原生设置/禁用状态继续可见。输入框不拦截pointer/touch/原生菜单，空白时也能长按粘贴。识别失败、取消、会话切换、草稿发生编辑或检查不通过时不会自动发送。

本插件适配当前实验性语音输入的页面结构和中文/英文按钮标签，不是稳定的 DSH 语音 API。自动发送依靠界面状态及 DOM 变化判断，不能权威证明插入文本来自本次语音识别；其他插件或脚本同时修改草稿时存在误发风险。如果不能接受此风险，请勿启用本插件。DSH 更新、更改语言或界面结构可能导致其失效。

## 如何启用回复朗读（0.1.10 新增，可选）

**安装插件不等于已经可以朗读。** 0.1.10 包含 Kokoro v1.1 中文 CPU 朗读桥接，但需要在运行 DSH 的电脑上自行准备 Python、依赖和模型，并开启 Host 配置。默认 Host 禁用、页面自动朗读关闭，不自动下载 Python 或模型。只使用麦克风输入，不需要安装任何 TTS 依赖。

实测 i7-8700：FP32 两线程可比播放速度更快生成；INT8 在这台 CPU 上反而显著更慢。常驻 worker 原型两短句峰值约828 MiB，长时间与其他 LLM 并发资源尚待验证。模型、三音色试听和完整实测见[历史 TTS 试验说明](https://github.com/rapidrabbitsliu/dsh-plugin-voiceinputwithpress/blob/v0.1.10/LOCAL-TTS-TRIAL.md)。

### 准备与配置

1. 将本仓库 **v0.1.10** 源码放到一个长期保留的独立目录（例如 `D:\voice-readout`），避免插件升级后 worker 路径变化。使用 Python 3.11 建立环境并安装依赖，不使用 CUDA：

   ```powershell
   # 在源码目录运行；此过程会从 Python 包索引安装依赖。
   py -3.11 -m venv .venv-tts
   .\.venv-tts\Scripts\python.exe -m pip install -r scripts/tts-requirements.txt
   ```
2. 优先从 [hf-mirror 中文 v1.1 ONNX 仓库](https://hf-mirror.com/onnx-community/Kokoro-82M-v1.1-zh-ONNX/tree/main) 或可信 ModelScope 镜像获取 `onnx/model.onnx`、`tokenizer.json`、`voices/zf_001.bin`、`voices/zf_002.bin`、`voices/zm_010.bin`。将下载后的五个文件**平铺**放到 worker 脚本所在项目的 `.local-tts/models/`，不要保留下载站的 `onnx/`、`voices/` 子目录：

   ```text
   <源码目录>/
     scripts/tts-worker.py
     scripts/tts_english.py
     .local-tts/models/
       model.onnx
       tokenizer.json
       zf_001.bin
       zf_002.bin
       zm_010.bin
   ```

   不要混用其他版本音色或词表。
3. 安装/升级到插件 **0.1.10**。在 DSH 插件配置中为 `dsh-plugin-voiceinputwithpress` 根组件提供以下 Host 配置（不是浏览器「设置 → 语音」中的参数；路径替换为源码目录下的实际绝对路径），保存并使该普通插件配置重新生效：

```yaml
ttsEnabled: true
pythonPath: 'D:\your-workspace\.venv-tts\Scripts\python.exe'
workerPath: 'D:\your-workspace\scripts\tts-worker.py'
```

`workerPath` 指向保留本地模型的项目副本；npm 包不包含模型或 Python 环境。默认只在第一次合成时启动进程，之后常驻直到停用；音色、语速是每次请求参数，不需要重新加载模型。配置命令路径只接受可信 Host 配置，不能由页面传入。

### 首次试听与日常朗读

4. 刷新 DSH 页面，打开 **设置 → 语音 → 启用声音 → 试听**。先确认试听能出声；如果提示服务未启用，检查上面的 Host 配置；如果提示模型/worker错误，检查依赖、文件布局和路径。
5. **手动朗读**：点击任意已完成助手回复顶部的喇叭。合成期间显示状态并禁用按钮；播放时再点停止。自动朗读开关关闭时也可逐条点播。
6. **自动朗读**：点击会话第二行「对话 / 轨迹」栏右侧总喇叭开启。只读开启后新开始、正常完成的回复，不补读历史。再次点击关闭并停止。
7. 如果 Safari 提示「声音待授权」，再点**同一条回复的喇叭**，直接播放保留的音频，不重复合成；页面刷新后可能需要重新进行用户点击。仍失败时到 **设置 → 语音 → 复制诊断日志**，保留错误类型和请求标识以便排查。

### 页面操作和限制

- 设置 →「语音」集中管理长按输入开关、长按触发时间（默认500毫秒，范围300～1500毫秒）、回复朗读开关、音色、语速、试听与诊断日志。关闭长按功能后麦克风仅保留原生短按录音；输入框在启用或关闭时都保持原生触摸与粘贴；已有设置自动沿用，新字段使用默认值。
- 对话页不再显示整块朗读配置栏，第二行「对话 / 轨迹」标签栏的最右侧只显示喇叭按钮：点击开启自动朗读并同步请求声音授权，再次点击关闭并立即停止当前播放。iOS Safari 刷新后可重新点亮喇叭；也可在「设置 → 语音」点「启用声音」和「试听」。播放器在当前页面复用，不承诺后台或锁屏播放；真实iOS新布局仍需用户验收。
- 自动模式仅处理当前聚焦主会话中开启后新开始且正常完成的轮次；历史、重连、HMR不补读。长期目标每轮正常完成不等于整个目标完成。
- 仅提交最终正文，跳过思考和工具日志，过滤代码、图片及链接地址。Markdown清洗是保守适配器，不是完整解析器；缩进正文也可能被省略。总长限制6000字、单段160字；只保留有限的预取，不无限合成长回复。
- 支持中文夹ASCII英文：通过Misaki中文前端的英文回调，使用已安装Misaki自带美式发音词典读普通词；全大写缩写逐字母读，iOS与ChatGPT有明确读法，未收录词逐字母兜底，不静默删英文。无需新增英语模型、Torch/BART或联网下载。仍使用所选中文音色，英语词典不做词性消歧，专有名词和整段英文的自然度需试听；日期、单位、多音字同样需核对。
- 当前会话每条已正常完成且有正文的助手回复顶部均有喇叭，历史回复也可点击手动朗读；未完成回复、推理和工具消息不提供朗读。合成等待时旁边显示「正在合成…」并禁用当前按钮，防止重复提交；实际播放时显示「正在朗读…」与循环声波，按钮恢复可点击以停止。浏览器明确返回NotAllowedError时保留当前音频、恢复按钮并提示点击该回复喇叭播放，第二次点击同步重试播放器、不重复合成；解码失败与浏览器中断单独提示，不一律误报授权。完成或失败后恢复按钮，旁边显示完成/具体错误；仍可用顶部总开关或设置页停止取消等待。点击另一条会替换当前朗读，不改变自动开关；关闭自动模式仍可手动朗读历史。按官方会话/消息身份定位，正文只从官方快照读取，不抓取DOM正文；尊重系统减少动态效果设置。设置页通用试听不标到消息上。
- 点击当前会话最后一条已完成助手回复正文、开始录音、发起新轮次、切会话、页面失焦或隐藏、停用插件均停止当前播放并取消请求。点击停止不关闭自动模式。只控制本插件创建的播放器。
- 音频由同源 owner-only 认证接口 `/api/voiceinputwithpress.tts` 返回当前浏览器，不在宿主扬声器播放，也不开放额外裸网络端口。取消正在合成的请求会终止worker以防串音，下次请求需重新加载。
- 「复制诊断日志」导出当前页面最近200条事件：分句序号、字符/英文字母数、音色语速、请求标识、HTTP结果、耗时及播放/授权错误。默认不记录正文、音频、认证信息或原始服务端异常；刷新页面会清空浏览器内存日志。宿主日志固定保存在worker项目的`.local-tts/logs/tts-host.jsonl`，有大小轮转上限。报错时请保留请求标识并复制日志，可区分校验、合成与Safari播放失败。
- 多标签页/多设备不保证全局只读一次。发布前本地构建已在现有GUI安装并验证试听完成；iOS自动播放修复尚待用户设备验收，mock测试不等于真实Safari验收。

## 开发验证

`npm run build` 生成 DSH 模块加载器使用的 `client.js`。`npm test` 覆盖原长按手势、正文清洗、播放状态及Host桥接模拟；Python worker输入验证用 `.venv-tts/Scripts/python.exe -B test/tts-worker.test.py`，真实Host/worker合成测试可显式设置 `TTS_HOST_SMOKE=1` 后执行Node测试。测试不替代真实浏览器与麦克风验收。前端复用 DSH 自带 React 和服务；可选本地TTS需要独立Python运行依赖。图形由 CSS/SVG 绘制，插件不包含外部图片或模型。代码 MIT 许可，模型授权单独核对。

开发时按 DSH 源码版本 `0.2.1-rc.3` 的页面契约适配；用户已在 iOS Safari 参与手动测试，但最新版本全流程和 PC 麦克风录音未独立完整验收，不承诺其他 DSH 版本兼容。

这是第三方独立插件，不修改 DSH 核心代码，与 DeepSeek 官方无隶属关系。
